# 全模块字体可放大只读审核（截图+静态分析）

## Goal

客户反馈游戏内字体偏小。在不改变布局、不改变节点 RectTransform/锚点、不让文字超出自身容器或与图标/按钮/主题元素重叠的前提下，评估哪些文字可以适当增大字号，输出可执行建议清单。

## Requirements

1. 截图取证：复用现有 Editor Shot 工具（M2Shot/M3Shot/M4Shot/M5Shot）在 batchmode 下输出 1920x1080 截图到 `Logs/`，作为视觉基准。工具自带冻结 Scene 哈希校验，保证 M2/M3 冻结 Scene 零改动。
2. 全量盘点：静态解析 5 个 Scene（M1~M5）中所有 TextMeshProUGUI / TMP_InputField / 旧版 UI.Text 的字号、自动缩放、溢出模式、换行设置、文本内容、自身 RectTransform 尺寸与父容器尺寸。
3. 覆盖运行时动态创建的文本：扫描 `Assets/Scripts/` 中代码创建的 label/气泡/提示/QA 面板等（含代码默认字号与容器尺寸）。
4. 对每个文本元素估算「换行行数不变/总高不超容器」前提下可放大的最大安全字号，并给出风险分级（可放大 / 谨慎 / 不建议）。
5. 用截图 + 视觉核查交叉验证静态结论，重点检查文字与图标/按钮/波形窗口/数字人/钢轨主题的重叠风险。

## 约束

- 纯只读：不修改任何 Scene、Prefab、素材、运行时代码；不新增 Assets 下脚本。
- M2/M3 Scene 为视觉权威（冻结），审计过程不得触碰。
- Unity 版本必须用 6000.3.21f1（ProjectVersion 指定）。
- 截图输出仅写入 `Logs/`（不入库）。

## Acceptance Criteria

- [ ] M2~M5 各有 1920x1080 截图且冻结 Scene 哈希校验通过（Shot 工具 exit 0）。
- [ ] 静态表格覆盖 5 个 Scene 全部文本组件（数量可对账）。
- [ ] 每条结论给出：当前字号 → 建议字号（或「不建议」），以及判定依据（容器余量/重叠风险）。
- [ ] 不产生任何 Scene/Assets 差异（git status 中 Assets 无本次新增改动）。

- 不处理 M1 开场引导视频内嵌字幕（视频素材内的字，非 UI 文本）。
- 轻量任务：PRD-only。
