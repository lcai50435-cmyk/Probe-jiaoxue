# 字体可放大只读审计报告（09-19）

## 方法

1. **截图取证**：复用现有 Editor Shot 工具（M2Shot/M3Shot/M4Shot/M5Shot），
   Unity 6000.3.21f1 batchmode 输出 1920x1080 截图（副本见 `research/screenshots/`）。
   工具自带冻结 Scene SHA-256 前后校验，全部 exit=0，M2/M3 冻结 Scene 零改动。
2. **静态全量分析**：`research/analyze_fonts.py` 解析 M1~M5 全部 5 个 Scene YAML，
   提取 149 个文本组件（TMP/Text/InputField）的字号、容器实际尺寸（锚点+sizeDelta 递归求解）、
   换行/溢出模式，按 Sarasa Gothic 度量（CJK=1.0em、行高 1.2em 保守）估算可放大上限。
   全表见 `research/scene-font-audit.md`。
3. **运行时盘点**：代码创建的 UI（问答气泡、QA 面板、台词云朵、漂浮提示等）
   逐个核对字号与容器，见 `research/runtime-font-sizes.md`。
4. **视觉核查**：judge 对 4 张截图逐区审查拥挤度/重叠风险，与静态结论互相印证。

## 结论总览

回答老板的问题：**可行，而且空间不小**——大部分"内容性文字"（标题、指令、步骤、按钮字）
都有 +2~4px 的安全余量，部分标题可更多；但有一批"仪表型小字"已经贴边，坚决不能动。

### ⚠️ 谨慎放大（+1~2px，需真机/Play 截图验收）

| 位置 | 现字号 | 建议 | 风险 |
|---|---|---|---|
| M3/M4 底部指令长句 InstructionArea/Title | 27 | 28 | M4 最长句（26.2em*28≈734）距容器 747 仅 13px |
| 漂浮动作提示 ModuleHintOverlay | 30 | 32 | 悬浮在钢轨主题图上方，框固定 600x78 放得下，但离图形元素近 |
| 数字人台词云朵（ModuleSpeechBubble） | 26 | 最多 28 | 云朵图固定（老板定稿），已带 16~26 自动缩字兜底；动它属样式合同，建议老板拍板 |
| M2"点击这里"提示 | 26 | 28 | 锚在按钮上方 8px，增大后更靠近按钮顶边 |

| 位置 | 现字号 | 原因 |

## 实施提示（后续任务用，本次未改任何字号）

- 全部建议都只是改 `m_fontSize`（或代码里对应 fontSize 常量），**不动任何 RectTransform/锚点/文案**，符合"不改布局"要求。
- M2/M3 Scene 冻结：其 Scene 内文本（模块标题、按钮字、波形刻度等）要改必须由老板手工改，
  或走"运行时覆盖不写回"的既有模式（如 stepHints 同款）；M4/M5 Scene 未冻结但同理建议 Setup 化处理。
- 运行时改写文案的提示行（步骤条/指令），改字号前用代码里的最长文案验证（本报告已验）。
- 顺手发现（未修）：`Assets/Editor/M4Shot.cs` 截图输出文件名误写为 `m3-shot_*`（复制粘贴笔误），本次审计已人工归档区分，建议后续任务修正。
