# M1 界面横屏适配与视觉优化

## Goal

解决用户反馈的两个问题并落地用户提出的三部分视觉整改建议：
1. **横屏适配**：确认/修复主流手机横屏（16:9、18:9、19.5:9、20:9）下的显示完整性，消除"部分内容看不见"的问题。
2. **视觉统一**：统一工具卡片展示规则、按钮尺寸、标题视觉重量，提升整体美观度。
3. 全程遵循项目"低代码优先"倾向：优先场景配置化修复，尽量不改/少改运行时代码。

## 背景与已确认事实（均来自代码/场景证据）

- Canvas 配置（`Assets/Settings/Scenes/M1.unity` CanvasScaler）：`ScaleWithScreenSize`，参考分辨率 **1920×1080**，`matchWidthOrHeight=0.5`。
  - **推算结论**：match=0.5 在 18:9 / 19.5:9 / 20:9 下垂直方向分别裁剪约 62 / 102 / 114 参考像素，底部 InputRow（130px）会被裁掉，即"内容看不见"在非 16:9 手机上是真实存在的。改 match=0（按高度匹配）可避免裁剪，横向富余。
- QAPanel：固定 **780px** 宽不透明抽屉（`Assets/Editor/M1QASetup.cs:40` `PanelWidth=780`），锚定右侧全高，打开时盖住 x∈[1140,1920]。
- 工具卡片网格：`物品` 容器 anchor(0.5,0.5)、pos(-394,-73)、size 1110.8×781.4，6 张卡片各 356×356，2×3 网格；卡片右边界 ≈1121，与 QAPanel 左边界（1140）仅 **~18px 间隙**，观感紧凑。
- 6 张卡片 Image 均为 `Type=Simple` 且 **`PreserveAspect=0`**（未勾选保持宽高比）→ 不同比例设备图被拉伸变形，视觉高低错落。
- 语音按钮 76×78、字号 30；发送按钮 130×78、字号 32（`M1QASetup.cs:257,268`）→ 尺寸/字号不一致。
- 左侧标题"请选择钢轨探伤工具"字号 **50**，右侧"向铁小探提问"字号 **34**（QAPanel Header）→ 视觉重量不匹配。
- 计数器 `0/200`（22 号）独立占 InputRow 顶部一行（`M1QASetup.cs:277-283`）。
- 顶部"标题栏"：全宽 160px 高灰条（anchor(0,1)-(1,1)）；卡片区左边界 ≈10.6px。
- 白板背景无 Sprite（纯色底），**场景中不存在网格线** → 用户建议"删网格线"无需执行。
- 字体：Sarasa Gothic SDF（`Assets/Editor/GenerateChineseFont.cs` 默认参数生成）；编辑器 Game 视图 1.7x 非整数缩放的模糊观感在真机 1:1 下会缓解，SDF 图集参数可优化。
- 右侧数字人/背景圆/对话框位于 x∈[1159,1899]，被 QAPanel 打开时完全遮盖（抽屉设计行为）。

## Requirements

编号 R1-R12，映射用户建议三大部分。

### 一、视觉对称（所有比例生效）

- **R1** 6 张工具卡片图片等比完整显示：图片在卡片内居中、四周均等留白、不拉伸变形（场景 Image 勾选 Preserve Aspect 即可）。
- **R2** 顶部标题栏与卡片网格左右边距视觉对齐（标题栏内容/装饰左边界对齐卡片网格左边界）。
- **R3** 卡片网格横向/纵向间隙统一；卡片底色统一（实现时核对，若已一致则无需改动）。
- **R4** ~~卡片底部统一工具名称条~~ **已决策：不加**（用户 2026-08-07 确认暂时不加，保持卡片结构不变）。
- **R5** 左右两栏标题字号/字重匹配（当前 50 vs 34，收敛到一致视觉重量）。

### 二、手机横屏适配

- **R6** 修复非 16:9 屏幕裁剪：`matchWidthOrHeight` 0.5 → 0（按高度匹配），18:9/19.5:9/20:9 下不裁剪、高度完整。
- **R7** 左右栏重分配：右侧 QAPanel 收窄（780 → **700px，已确认**），左侧卡片区域右移/放大（卡片 356 → 372），保证 2×3 卡片完整、不压扁。
- **R8** 压缩非核心垂直空间：标题栏高度收窄（160 → ~120）、卡片间隙缩小、计数器挪进输入框内部右下角（不再独占一行）；聊天记录区占剩余大头。
- **R9** 底部输入行防挤压：输入框/语音/发送保持单行，按钮不换行、尺寸不缩水，由输入框承担压缩。
- **R10** 滚动兜底（条件性）：若在目标比例下仍放不下，仅允许左侧整体垂直滚动、网格结构不变；右侧聊天区独立滚动（已有）。match=0 修复后预期不需要，先不做（YAGNI）。

### 三、问答面板细节

- **R11** 关闭 × 按钮与面板标题文字垂直居中对齐（核对当前 64×64 按钮 vs 34 号标题的视觉中心）。
- **R12** 输入框 / 语音 / 发送三者高度对齐，消除高低错位。

## Acceptance Criteria

- [ ] 在编辑器 Game 视图依次以 16:9、18:9、19.5:9、20:9 纵横比验证：界面完整无裁剪，顶部标题栏与底部输入行均完整可见。
- [ ] 6 张卡片图片全部等比居中显示，无拉伸变形，四周留白均匀。
- [ ] 语音/发送按钮高度一致、字号一致；输入框三者单行排布，任何比例下不换行。
- [ ] 左右标题视觉重量匹配（字号一致或观感一致）。
- [ ] 计数器显示在输入框内部，不再独占一行。
- [ ] 卡片网格与标题栏左右边界视觉对齐。
- [ ] 面板打开时，2×3 卡片网格完整可见，无遮挡、无贴边（间隙 ≥ 用户可接受的视觉余量）。
- [ ] 场景与脚本改动均通过 M1Setup/M1QASetup 幂等校验（重复执行不产生重复对象）。
