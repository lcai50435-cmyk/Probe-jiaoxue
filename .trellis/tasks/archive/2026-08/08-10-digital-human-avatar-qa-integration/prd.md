# 数字人全身头像与问答动画联动

## Goal

在 M1 中把现有静态数字人升级为可折叠的全身视频数字人，并让其在 DeepSeek 问答期间始终可见：平常播放待机动作，请求期间播放思考动作，回答逐字显示期间播放讲解动作；聊天面板与数字人并列，不再相互遮挡。

## Background

- M1 参考分辨率为 1920x1080，当前 QAPanel 是右侧宽 780px 的全高抽屉，会覆盖既有数字人区域。
- `M1QAPanel.OnAnswerStateChanged` 已发布 `Idle / Thinking / Speaking`，但没有动画消费者。
- 用户已确认数字人允许适当缩小，并要求支持全身态与头像态切换。
- 用户已确认：头像态长按提问时自动展开全身，聊天结束后恢复提问前的头像态。
- 现有 `UI-LumaKey` 和 `VideoPlayer -> RenderTexture -> RawImage` 已在 M1 开场引导中验证。
- 已抽帧确认三个指定 MP4 的人物与白色描边已经制作完成，但编码均为 H.264 `yuv420p`、无 Alpha，四角是纯黑；它们是可直接键控的黑底素材，不是透明成片。
- 前置任务 `.trellis/tasks/08-10-digital-human-three-animations` 负责三个指定 MP4 的静音导入配置；本任务不得重复或反向覆盖其修改。
- 首轮 Unity 验收反馈：常驻全身视频缩小后白色描边发糊/锯齿；头像位于右上角而非全身舞台位置；头像切回全身后 VideoPlayer 停在静帧。

## Requirements

- **R1 三态动画**：全身态下，`Idle` 循环待机视频，`Thinking` 循环思考视频，`Speaking` 循环讲解视频；每次切换从目标片段开头播放。
- **R2 黑底抠像与静音**：全身视频使用现有 `UI-LumaKey` 材质，`VideoPlayer.audioOutputMode = None`，不得影响现有有声开场引导。
- **R3 全身/头像切换**：聊天关闭时，短按数字人可在全身态和折叠头像态之间切换；默认进入全身待机态。
- **R4 长短按互斥**：长按只打开问答面板，不得在抬手时额外触发短按折叠。
- **R5 自动展开恢复**：头像态长按时先记忆头像态并自动展开；面板完全关闭且回答生命周期回到 `Idle` 后恢复头像。原本为全身态则关闭后保持全身。
- **R6 面板期间锁定全身**：问答面板打开期间忽略短按折叠，保证思考和讲解动作可见。
- **R7 中途关闭**：Thinking/Speaking 期间关闭面板不取消现有请求或逐字显示；数字人保持全身，回到 Idle 后再执行待恢复的头像态。
- **R8 并列布局**：QAPanel 位于数字人左侧，数字人位于独立右侧舞台；二者无视觉遮挡，数字人不被 Blocker 压暗或拦截。
- **R9 低代码与幂等**：场景结构由 `M1QASetup` 幂等生成；仅新增一个用于订阅 C# 事件、切换视频和协调显示形态的 runtime 组件，默认不超过 150 行；素材、尺寸和引用通过 Inspector 注入。
- **R10 兼容既有功能**：保留文字输入、语音占位、消息列表、长按入口、DeepSeek 生命周期、M1 工具提示气泡和开场引导行为。
- **R11 素材约束**：仅使用用户指定的三个 MP4：`A-01 待机动画/待机动画.mp4`、`A-02讲解动画/讲解动画2.mp4`、`A-03 思考动画/思考动画.mp4`，以及 `A-05 折叠态头像.PNG`；不使用对应 WebM，不修改、转码、删除或下载素材。
- **R12 边缘质量**：常驻数字人使用独立于开场引导的 LumaKey 材质参数和高质量缩小采样，改善小尺寸白描边的模糊/锯齿，不改变全局 Shader 或开场引导材质表现。
- **R13 同位切换**：头像态与全身态使用同一个舞台视觉中心，切换时不得跳到屏幕右上角。
- **R14 恢复播放**：任何 Avatar -> FullBody 转换都必须根据当前 AnswerState 恢复并继续播放对应视频，不得停在静帧。

## Acceptance Criteria

- [ ] 1920x1080 下聊天面板和缩小后的全身数字人并列完整可见，无重叠、裁切或文字溢出。
- [ ] 默认显示全身待机；短按可稳定切换全身/头像，长按不会误触发短按。
- [ ] 头像态长按后自动展开并打开面板；Idle 关闭后恢复头像；全身态打开后关闭仍保持全身。
- [ ] DeepSeek 成功流程严格表现为 `Idle -> Thinking -> Speaking -> Idle`，视频与状态一致且循环连续。
- [ ] 空 Key、网络失败和空回复均回到 Idle，不遗留忙碌或错误动画状态。
- [ ] Thinking/Speaking 中关闭面板时请求继续，生命周期完成后才恢复提问前头像态。
- [ ] 三个指定 MP4 均通过现有 LumaKey 在显示阶段去除纯黑底，无可见黑色矩形或意外音轨；原视频文件不变，开场引导仍保留原有音轨。
- [ ] QAPanel 打开时 Blocker 能阻止底层操作，但不会遮住或压暗数字人。
- [ ] `M1QASetup` 连续执行两次不创建重复节点/组件，不覆盖 Inspector 中已替换的非空素材引用。
- [ ] 1280x720、1920x1080、2436x1125 横屏下无明显重叠；窄屏允许数字人按配置缩小但保持全身完整。
- [ ] 新 runtime 脚本不超过 150 行；所有运行时查找路径与 Setup 生成层级一致。
- [ ] 常驻数字人在实际显示尺寸下白色描边连续、无明显黑边/锯齿；开场引导抠像效果不变。
- [ ] 头像显示在全身数字人的同一视觉中心；头像切回全身、头像长按自动展开后，当前状态视频立即恢复运动。

## Out of Scope

- 修改 `UI-LumaKey` Shader 算法或 M1 开场引导逻辑。
- 重写 DeepSeek 网络请求、聊天消息 UI 或 M1 工具选择流程。
- Git 历史清理、提交和推送。
