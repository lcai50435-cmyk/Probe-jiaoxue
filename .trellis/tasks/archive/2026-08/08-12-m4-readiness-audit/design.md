# M4 模块实现就绪度审计 - 审计设计

## 1. 结论模型

对每个维度分别判定：

- **已具备**：仓库中有权威合同和可直接使用的实现载体，不依赖未完成前置任务。
- **有条件具备**：可以开始独立实现，但完整验收依赖明确且可控的补齐项。
- **阻塞**：缺少产品决定、必要 Scene/素材或稳定公共能力，继续实现会导致返工或复制错误业务。

总体结论同时回答两个问题：当前能否开始 M4；当前能否完成 M4 全量验收。

## 2. 证据优先级

1. `文档/仿真交互动画技术规格书.docx`：M4 专属业务参数与流程。
2. `文档/功能文档.docx`：预算内实现/降级范围与素材责任。
3. `.trellis/spec/unity/ugui-module-template.md`：当前生效的 Unity 视觉、Setup、复用和验收合同。
4. 冻结的 M3 Scene、当前 runtime 代码和素材实物：判断可落地性，不能反向覆盖产品参数。
5. AI 新增版规格：数字人话术和全局交互增强；与已确认项目约定冲突时列为未决项。

## 3. 审计维度

| 维度 | 核心问题 |
|---|---|
| 产品合同 | 轨腰位置、向上 10°、80→30mm、40mm、波形区间、测距和出口是否明确 |
| Scene/UGUI | M4 Scene/Setup 是否存在；能否按未冻结模块规则采用 M3 基线生成 |
| 素材 | 正视钢轨、透明钢轨、K2.5、40mm 尺、伤损/声束、波形参考是否可直接使用 |
| Runtime | QA/数字人、波形、拖拽、尺子、帮助是否真正参数化，是否仍含 M3 硬编码 |
| 串联 | M3→M4、M4→M5、Build Settings 是否具备且是否应延后 |
| 验证 | Unity 编译、Play Mode 烟测、三视口截图和 Scene 幂等是否有可复用工具链 |

## 4. 冲突处理

- 耦合剂：老板已确认采用技术规格及 M3 口径，进入 M4 自动展示约 2 秒已涂薄膜，不重复点击涂抹。
- 完成出口：老板已确认以 Inspector `UnityEvent` 实现自动串联 M5；未配置时保持完成态并显示“下一模块待接入”。

## 5. 输出

生成 `audit.md`，包含证据表、总体结论、阻塞项、非阻塞缺口、可复用清单和建议实施顺序。只读审计不修改业务代码、Scene、素材或 Build Settings。
