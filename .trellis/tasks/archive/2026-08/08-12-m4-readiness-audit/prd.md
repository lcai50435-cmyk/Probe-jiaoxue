# M4 模块实现就绪度审计

## 目标

基于仓库中的产品文档、Unity Scene、素材、现有运行时组件和项目规范，判断 M4 当前是否已经具备实现条件，并输出可追溯的“已具备 / 有条件具备 / 阻塞”结论及最小补齐清单。

## 已确认产品决定

- M4 沿用 M3 的耦合剂口径：进入模块后自动展示约 2 秒已涂浅蓝薄膜，随后直接进入定位；不新增“涂抹耦合剂”按钮。
- 40mm 测距完成后进入完成态，通过 Inspector 配置的 `UnityEvent` 自动串联 M5；M5 未配置时稳定显示“下一模块待接入”，不报错、不创建假 M5。
- 老板 2026-08-13 确认钢轨红色区域为唯一损伤目标：探头入射点到红色损伤中心为 40mm，绿色检测束命中和尺子 `40mm` 锚点均以该点为目标；焊缝熔合线只作视觉参照。

## 要求

1. 审计 M4 的业务目标、教学流程、角度/距离/缺陷/波形等专属参数是否有权威定义，识别文档间冲突和未决产品问题。
2. 审计 M4 Scene、Build Settings、UGUI 节点及 Setup 工具是否存在，并判断能否采用 M3 视觉基线创建未冻结模块。
3. 审计钢轨视图、探头、尺子、伤损、音频、数字人等素材是否存在、可区分且可直接接入。
4. 审计 M1 QA/数字人、M2 波形以及 M3 参数驱动组件的实际复用边界，禁止把复制其他模块状态机视为实现条件。
5. 审计 M3→M4、M4→M5 出口和独立验收条件，但不在本任务中修改 Build Settings 或创建假场景。
6. 结论必须区分：无需前置补齐即可开工、可边实现边补齐、开工前必须确认或补齐。

## 验收标准

- [x] 每项结论均引用仓库文件、Scene/代码证据或明确说明“仓库中不存在”。
- [x] 给出总体就绪度结论，并说明“能否开工”与“能否完整验收”是否不同。
- [x] 列出阻塞项、非阻塞缺口、可复用资产和建议实施顺序。
- [x] 明确是否需要老板补充产品决定、视觉节点或外部素材。

## 范围外

- 实现 M4 runtime、Setup 或 Scene。
- 修改 M1/M2/M3 冻结 Scene 或现有业务行为。
- 搜索、挑选或下载外部素材。
- 配置 M3→M4、M4→M5 串联。
