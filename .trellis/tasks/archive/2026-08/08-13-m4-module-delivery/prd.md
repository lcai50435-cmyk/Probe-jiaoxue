# M4 轨腰探测模块交付

## 目标

分两阶段交付 M4：先完成轨腰部位探测的静态 Scene 与 UGUI 线框并由老板审核冻结，再以冻结后的真实节点和素材为依据，完成 M4 运行时实现规划文档。

## 子任务与顺序

1. `08-13-m4-static-scene-ugui`：创建 M4 静态 Scene、幂等 Setup、完整三视口截图并完成视觉审核。
2. `08-13-m4-runtime-planning`：仅在静态 Scene 审核并冻结后启动，编写 M4 runtime 的 `prd.md`、`design.md`、`implement.md`，不在该子任务中实现代码。

第二个子任务依赖第一个子任务产出的冻结 Scene 哈希、真实层级、节点引用和最终视觉决定，不能提前用虚构节点规划。

## 跨任务要求

- M4 默认采用 M3 冻结视觉基线，但只复用页面骨架、视觉令牌与公共链路，不复制 M3 Scene YAML、fileID 或业务状态机。
- M4 专属合同为：轨腰最上端、向上 10°、80mm 起点、40mm 检出并锁定、进入时 2 秒已涂耦合剂展示、三步流程和可配置 M5 出口；80→30mm 仅保留为波形参考域，玩家不在检出后继续扫描至 30mm。
- 老板 2026-08-13 确认钢轨红色区域为唯一损伤目标：探头入射点到红色损伤中心的距离为 40mm；绿色检测束命中、报警和尺子 `40mm` 锚点均使用该目标，`WeldLine` 仅作视觉参照。
- 同一把多功能尺承担定位阶段 10°校角和检出后 `0/40mm` 双点复测，不创建第二把业务尺或以自动测距代替玩家操作。
- M2/M3 冻结 Scene、既有业务代码和 Build Settings 均不得在这两个子任务中修改。
- M4 静态阶段不新增 runtime 脚本；运行时规划阶段不实现 runtime 代码。

## 验收标准

- [ ] M4 静态 Scene 在三视口通过老板视觉审核并记录冻结 SHA-256。
- [ ] M4 Setup 在冻结前满足连续执行幂等，冻结后按项目规则收缩为只读打开器。
- [ ] M4 runtime 规划基于冻结后的真实节点，以红色损伤中心为唯一几何目标，覆盖尺子双模式、绿色检测束命中和 40mm 检出锁定，不包含虚构路径或复制其他模块状态机的方案。
- [ ] 两个子任务均完成各自检查，且 M1/M2/M3 Scene 与 Build Settings 不因本任务变化。

## 范围外

- M4 runtime 实现、M3→M4/M4→M5 串联和 Build Settings 修改。
- M5/M6 Scene 或业务实现。
- 外部素材搜索、下载或正式美术重制。
