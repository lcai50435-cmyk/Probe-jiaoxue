## 1. 部署步骤（普通云函数，非 HTTP 函数）

1. 在微信开发者工具打开 `Builds/WXExport/minigame`（或用现有微信小游戏项目直接添加该目录）。
2. 左侧资源管理器出现 `cloudfunctions/deepseek-proxy`（因 `cloudfunctionRoot` 已声明）。
3. 右键该目录 → 「上传并部署：云端安装依赖（不上传 node_modules）」，云端自动
   `npm install`（wx-server-sdk ~2.6.3）并运行 `index.main`。
   - 若控制台已手动创建过同名函数，选择「云端已有函数」覆盖更新，或先在控制台删除。
4. CloudBase 控制台 → 云函数 → deepseek-proxy → 配置 → 环境变量：
   - `DEEPSEEK_API_KEY`：**轮换后的新 Key**（旧 Key 已进过客户端风险范围，必须作废重建）。
   - `DEEPSEEK_MODEL`：`deepseek-chat`（可选）。
   - `DEEPSEEK_SYSTEM_PROMPT`："铁小探"人设（可选，默认值同客户端旧人设）。
5. 确认函数超时 ≥ 35s、内存 128MB+；`main` 入口为 `index.main`。
6. 客户端配置：`Assets/Resources/AiProxyConfig.asset` 已填
   `envId = cloud1-d6gmycfs6b37edb43`、`functionName = deepseek-proxy`、`timeout = 40`。
   重新导出微信后即生效。

## 2. 与旧 HTTP 方案的区别

- **普通云函数不需要 request 合法域名**：调用走微信 `WX.cloud.CallFunction` 通道，
  不经过 HTTP 网络栈，无需在微信公众平台配置服务器域名，也不需要开启云函数 HTTP 访问服务。
- 客户端不再构造 `https://` URL、不设置任何 Authorization 头；Key 只存在于云函数环境变量。
- Android/Editor 仍走 `DeepSeekConfig` 直连，不受本方案影响。

## 3. 安全要点

- 旧 DeepSeek Key 已随 `DeepSeekConfig.asset` 进入过 WebGL 构建产物，**必须在 DeepSeek
  平台作废并换新**；新 Key 只存在于云函数环境变量。
- 云函数日志只输出错误类别（`upstream_5xx` 等），不输出问题正文与凭据。
- 按 `cloud.getWXContext().OPENID` 用户限流（同用户 60s/10 次，内存计数）；体验版规模
  足够，公开发布前建议换成集中式计数（Redis/数据库）。
