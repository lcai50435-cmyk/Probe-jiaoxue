# M1 开场引导动画 — 实现记录与踩坑清单

> 2026-08-08 · M1 模块
> 功能：进入游戏先播放引导动画（卡通人物悬空讲解，约 15 秒），播完再正式开始。
> 本文记录最终方案、实现架构、以及本次踩过的所有坑，供后续模块（M2/M3）或其他视频功能复用。

---

## 一、最终效果

- 进入 M1 场景 → 游戏立即**时间静止**（`Time.timeScale = 0`），游戏 UI 不可交互
- 全屏**半黑遮罩**（黑度 0.8）压暗游戏画面
- 卡通人物**居中、放大、悬浮**在画面上（视频黑底被抠除，人物像贴纸浮在遮罩上，带白色描边发光感）
- 人物周围透明区域直接露出被压暗的游戏画面，**没有任何黑色方块**
- 约 15 秒播完（含音轨）→ 自动恢复游戏
- **首次进入**：强制完整观看，不可跳过；**非首次**：仍自动播放，但可点击遮罩任意处或右上角"跳过"按钮跳过
- 用 `PlayerPrefs` 记录首次状态

## 二、实现架构

### 层级结构（场景内，由 `M1Setup.cs` 幂等生成）

```
画板 (Canvas, ScreenSpaceOverlay, sortingOrder 0)
└── 引导遮罩 (嵌套 Canvas, sortingOrder 100) ← 挂 M1IntroVideo 脚本
    ├── 半黑遮罩   (全屏 Image 黑 0.8 + Button 点击跳过, raycastTarget 挡点击)
    ├── 引导视频   (RawImage 高度适配居中 + AspectRatioFitter + VideoPlayer)
    └── 跳过引导   (右上角按钮, 首次隐藏)
```

### 关键组件

| 组件 | 说明 |
|---|---|
| `M1IntroVideo.cs`（runtime，~120 行） | 首次检测、暂停/恢复、预解码、播放/跳过控制 |
| `UI-LumaKey.shader`（Assets/Shaders/） | 黑底抠像：亮度 < 阈值变透明，人物保留 |
| `UI-LumaKey.mat` | 材质（Setup 自动创建），可调 Key Threshold / Key Smooth |
| `M1Setup.cs`（Editor） | 幂等搭建 + 自动修复历史问题 |

### 视频播放链路

```
VideoPlayer → RenderTexture(1080×1450) → RawImage（挂 LumaKey 材质抠像）
```

- 用 RenderTexture 而非相机渲染，保证视频层叠在遮罩**之上**（遮罩在游戏 UI 之上、视频在遮罩之上）
- 竖屏视频 1080×1450，**高度适配居中**（方案 A）：人物顶天立地、不变形、不裁切，两侧留黑由遮罩覆盖

### 播放流程（预解码，杜绝开头卡顿）

1. `Awake`：创建 RenderTexture → `Time.timeScale = 0` → `player.Prepare()` 后台预解码 → 协程 5 秒超时兜底（`WaitForSecondsRealtime`）
2. `Start`：写 PlayerPrefs 首次标记 → 显示遮罩（预解码期间盖住画面防穿帮）→ 已准备好则立即播放
3. `prepareCompleted` 事件 → 播放（此时解码已就绪，开头零卡顿）
4. `loopPointReached`（播完）或点击跳过 → 隐藏遮罩、`Time.timeScale = 1` 恢复

## 三、踩过的坑（按严重程度排序）

### 坑 1：HLSL `smoothstep` 参数顺序写反 —— 抠像完全反转 ⚠️ 最隐蔽

**现象**：黑底去不掉、人物反而被抠成透明，试了多轮颜色空间调整都无效。

**根因**：HLSL 要求 `smoothstep(edge0, edge1, x)` 且 **edge0 < edge1**（x≤edge0→0，x≥edge1→1）。写成 `smoothstep(阈值+羽化, 阈值, x)` 后，d3d11 下行为**完全反转**：背景保留（黑底不透明）、人物抠掉（透明）。

```hlsl
// ❌ 错误：edge0 > edge1，行为反转
half keyAlpha = smoothstep(_KeyThreshold + _KeySmooth, _KeyThreshold, lum);
// ✅ 正确：edge0 < edge1
half keyAlpha = smoothstep(_KeyThreshold, _KeyThreshold + _KeySmooth, lum);
```

**预防**：写 smoothstep 前先默念"小值在前、大值在后"；用离线脚本模拟算法后再提交。

### 坑 2：嵌套 Canvas 默认只有 100×100 —— 内容全挤在屏幕中心

**现象**：引导动画显示成屏幕中央一小块（74×100），比例完全不对。

**根因**：代码 `new GameObject(name, typeof(Canvas))` 生成的 RectTransform 默认锚点 (0.5,0.5)、尺寸 100×100。嵌套 Canvas 不会自动全屏。

**修复**：创建后必须手动 `StretchFullScreen`（anchor 0~1，offset 0）。

### 坑 3：Linear 色彩空间下直接按亮度抠像，人物暗部被误抠

**现象**：人物深色部分（黑裤、帽檐、阴影）变透明，只剩亮色衣服和白描边。

**根因**：项目为 Linear 色彩空间，RenderTexture 内是**线性值**。人物暗部 sRGB 亮度 8~40（0.03~0.16），转线性后仅 0.0004~0.019，全部低于阈值被当成背景。

**修复**：键控前先把采样值转回 sRGB 空间：

```hlsl
inline half3 ToSRGB(half3 c)
{
    #ifdef UNITY_COLORSPACE_GAMMA
    return c;                     // Gamma 项目原样
    #else
    return LinearToGammaSpace(c); // Linear 项目转回 sRGB
    #endif
}
```

### 坑 4：Unity 6 没有 `LinearToSRGB` 函数

**现象**：shader 编译报错 `undeclared identifier 'LinearToSRGB'`。

**根因**：该函数是较新 Unity 的别名，Unity 6 的 `UnityCG.cginc` 里只有 `LinearToGammaSpace`（线性→sRGB）和 `GammaToLinearSpace`（sRGB→线性）。

**修复**：用 `LinearToGammaSpace` + `UNITY_COLORSPACE_GAMMA` 宏判断封装（见坑 3 代码）。

### 坑 5：VideoPlayer 开头卡顿 —— 需要预解码

**现象**：播放开头几百毫秒卡顿。

**根因**：`Play()` 时才临时解码，VP9 解码 + 音轨同步需要时间。

**修复**：`Prepare()` 预解码 + `prepareCompleted` 事件后再 `Play()`；加超时兜底防解码异常永久黑屏。
注意：超时协程必须用 `WaitForSecondsRealtime`——**`Invoke`/`WaitForSeconds` 受 `timeScale=0` 影响不会执行**！

### 坑 6：API 细节小坑

| 坑 | 修复 |
|---|---|
| `VideoClip.width/height` 是 `uint` | `new RenderTexture((int)clip.width, ...)` |
| `VideoPlayer.loop` 不存在 | 属性名是 `isLooping` |
| C# 字符串插值里三元表达式 | 必须加括号 `{(a ? b : c)}`，否则 `:` 与插值格式符冲突 |

### 坑 7：batchmode 自动化测试的坑

- **batchmode 不会恢复上次打开的场景**：`-executeMethod` 里必须自己 `EditorSceneManager.OpenScene` 再执行（加了 `SetupM11Batch` 批处理入口）
- **batchmode + `EnterPlaymode` 在这台机器上不可靠**：d3d12 图形设备报错 + License 校验失败，会导致卡死/断言崩溃。**PlayMode 自动化测试放弃，改由人工在编辑器验证**
- batchmode 测试可能写入 PlayerPrefs 残留，验证后要清理（见坑 8）

### 坑 8：PlayerPrefs 测试残留

Windows 上 PlayerPrefs 存在注册表：`HKCU\Software\Unity\UnityEditor\<公司名>\<产品名>`，key 名带 hash 后缀（如 `M1_Intro_Seen_h4231413258`）。
测试后记得删除，否则"首次进入"状态被污染。

### 坑 9：webm vs mp4

- **webm（VP8/VP9）**：Unity 导入为 VideoClip 正常、无警告；但 **Windows 运行时解码依赖系统 Media Foundation**，部分机器可能播不了
- **mp4（H.264）**：导入有 `Unexpected timestamp values` 警告（非 baseline profile），Unity 自动修正，一般可正常播
- 稳妥做法：Setup 里 webm 优先、mp4 兜底（`LoadAssetAtPath ?? LoadAssetAtPath`），运行时脚本不关心格式

### 坑 10：文件被外部手改导致状态失控

本次排查中 shader 文件被手改过（内容与我维护的版本不一致），增加了排查难度。**约定：AI 维护的文件（shader/脚本）头部写明"勿手改"；调参走材质/Inspector**。

## 四、可调参数

| 位置 | 参数 | 默认 | 说明 |
|---|---|---|---|
| `UI-LumaKey.mat` Inspector | Key Threshold | 0.02 | 黑底抠像阈值（sRGB 亮度），调大抠得更狠 |
| `UI-LumaKey.mat` Inspector | Key Smooth | 0.015 | 边缘羽化宽度，调大边缘更柔和 |
| 场景 M1IntroVideo | allowSkipOnReplay | true | 非首次是否可跳过 |
| 场景 M1IntroVideo | prepareTimeout | 5 | 预解码超时兜底（秒） |
| `M1Setup.cs` `IntroDimAlpha` | 遮罩黑度 | 0.8 | 改后重跑 Setup |
| 半黑遮罩 Image | color.a | 0.8 | 也可直接改场景 |

## 五、复用指南

- **其他模块加引导**：复制"引导遮罩"层级 + 挂 M1IntroVideo，换 VideoClip 即可（脚本与 shader 通用）
- **换视频**：替换 VideoClip 引用即可；若新视频不是"纯黑背景 + 亮色主体"，需重新评估抠像阈值
- **普通视频播放（无需抠像）**：去掉 RawImage 的 LumaKey 材质即可
- **重置首次状态**：删注册表 `HKCU\Software\Unity\UnityEditor\DefaultCompany\数字人教学` 下的 `M1_Intro_Seen_*` 键
